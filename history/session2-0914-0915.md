## 2. Network activity investigation → NFR-10 and G-14

Jeff noticed real network activity while running `testAgent.py` and asked
whether PaddleOCR or Ollama was responsible.

Research found multiple GitHub issues (PaddleX #4578, PaddleOCR #16620,
#16639) documenting that PaddleX's OCR pipeline contacts four external
model-hosting platforms (huggingface.co, modelscope.cn, aistudio.baidu.com,
paddle-model-ecology.bj.bcebos.com) during initialization, in some cases even
with a valid local model cache — with no confirmed working way to fully
suppress it. Ollama on Windows separately runs a background auto-updater
(`ollama.com/api/update`), unrelated to inference.

Jeff then did his own empirical investigation with Windows Task Manager,
Resource Monitor, and Sysinternals TCPView across two `testAgent.py` runs.
Finding: with every PaddleX model already cached, the only TCP activity from
the OCR/LLM stack was `python.exe` ↔ `ollama.exe` ↔ `llama-server.exe`, all
over loopback (127.0.0.1/::1). No connection to any of the four external
hosts appeared. Other network activity in the same captures (`claude.exe`,
Multipass, Postgres, Spotify) was confirmed unrelated.

This was written into `docs/Requirements.md` as:
- **Section 8, Investigation Findings** — the full research + empirical
  findings, precisely scoped: a *warm-cache* result from *snapshot-based*
  tools, not a *cold-start* result from a *packet-capture* tool, so it
  doesn't settle whether the upstream-documented behavior would appear on a
  clean cache or fully offline.
- **NFR-10** — states the actual requirement (no outbound network
  dependency, no document-content exfiltration) but marked explicitly
  **unverified, not met**, with the specific follow-up test spelled out:
  clear/relocate the PaddleX model cache (and separately try fully offline),
  rerun from clean state under Wireshark on loopback *and* the physical/
  Wi-Fi adapter, and create a task under `tasks/` + a test under `tests/` so
  it's reproducible.
- **G-14** in the gap list — the intent document didn't say whether "runs
  locally" means "no calls once cached" or the stricter "no calls ever,"
  and only the cold-start test can show which the implementation actually
  satisfies. (Note: the new `docs/Intent.md` — see "Unreviewed changes" —
  appears to answer this now; G-14 should be revisited.)

## 3. BR-6 — the explicit-requirement gate

Jeff raised a process point: he expected some adaptation of Gem Iroko's
process for organization-specific governance (e.g., a `CLAUDE.md`-style
"always seek Security and Architecture Review approval" instruction), but
said he'd rather make such gates explicit requirements than organization-
dependent instructions.

Discussed and agreed: a process instruction in an agent file is guidance
about *how the work gets done* — organization/tool-dependent and not
independently testable. A requirement states the *property the system must
have* and is portable and falsifiable. Added to `docs/Requirements.md`:

> **BR-6** — Any requirement whose failure mode is data exfiltration,
> unauthorized network access, or credential exposure shall not be
> considered satisfied until it has an explicit, named acceptance criterion
> and a passing, recorded test result. A requirement in this category with
> no such test is an open gap, not an assumed pass.

BR-6 explicitly names NFR-10 as its first governed case — and NFR-10
currently fails that gate (no passing recorded test yet), so it stays open.

## 4. Git setup

Jeff ran `git init` locally and created a GitHub repo (`jgriffithGitHub/
OCRAgent`), then needed help connecting them:
- `git remote add origin <url>`, then commit, then
  `git branch -M main` / `git push -u origin main`.
- Push was rejected (non-fast-forward) because GitHub had auto-created a
  README.md commit with no shared history with the local repo.
- `git pull origin/main main` (invalid syntax) → `git pull origin main`
  (correct syntax, but failed with "refusing to merge unrelated histories").
- Fixed with `git pull origin main --allow-unrelated-histories --no-edit`,
  which merged cleanly (only README.md was new), then `git push -u origin
  main` succeeded. `main` now tracks `origin/main`.
